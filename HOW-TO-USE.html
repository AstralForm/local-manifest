Account Operation

Account Operation JIRA generator

Use this tool to write complete Jira tickets without rebuilding the description from scratch. Pick the board that matches the work. If the destination board does not have a set template, use Rippling Standard template. Preview the ticket, then copy it into Jira.

Templates included

  • Rippling Standard template — use this when the board does not have a set template
  • Global Payroll
  • AOPS - Invoice Waiver
  • AOPS - One-Time Refund
  • AOPS - One-Time Charge
  • BEXC — Account exemptions
  • Bill - Monetization Platform
  • Payment Ops (PO - JIRA)
  • FLEX JIRA
  • Tax Specific (PF JIRA)

When no board is selected, the generator shows SLAs vs Priority (TTR by P0–P4).

Tips on how to use this template

  1. Select the Jira board that matches the work. Do not mix formats (for example, do not use Global Payroll for an AOPS refund). If the board has no set template, choose Rippling Standard template.
  2. Fill every required field for that board. Empty fields are left out of Preview on purpose so the ticket stays clean.
  3. AOPS titles must follow: Client Name | Brief description of issue // For reference or Not For reference. Use the title box for “Client Name | Brief description”, then pick For reference / Not For reference from the dropdown. Preview adds the suffix.
  4. AOPS - Invoice Waiver and AOPS - One-Time Refund: enter the dollar amount. Amount Category and Required Approvers fill from this matrix:
    Amount Required Approvers
    Under $1,000No approver needed
    $1,000 – $5,000Requester's Manager
    $5,000 – $10,000Requester's Manager + Director
    $10,000 – $50,000Requester's Manager + Director + VP
    $50,000+Requester's Manager + Director + VP + Vipin Sethi (Accounting)
    Attach AM approval (Slack thread or screenshot) in troubleshooting.
  5. AOPS - One-Time Charge does not use Amount Category or Required Approvers. Enter Charge Amount only, plus AM approval.
  6. Checkboxes (LogRocket, debugger, screenshots, demo, playbooks, Risk Eval) only show follow-up fields when checked.
  7. Set “Have you included all requested information?” to Yes before Create Jira Text. That confirmation is a quality gate and is not pasted into Jira.
  8. Use Preview to confirm numbered headings and “Label: value” bullets look like a real Jira description.
  9. Click Copy for Jira, then paste into Jira with Command+V (Mac) or Ctrl+V (Windows). Do not use Shift+Command+V / Ctrl+Shift+V, or heading formatting is lost.
  10. Pick Jira priority to match customer-task SLAs:
    • P0 Highest: 2 business days (critical blockers / sensitive escalations)
    • P1 High: 7 business days
    • P2 Medium: 14 business days
    • P3 Low: 21 business days
    • P4 Lowest: no TTR SLA; set customer expectations and solve in Support
  11. Board-specific reminders:
    • Bill / Monetization: Cursor Bot or Billing Bot thread is mandatory.
    • FLEX: choose the correct Benefits project and issue type Customer Task.
    • Tax (PF): title as USGP or Legacy // Account name // short description. CTI and Lead who approved the ticket are required.
    • Payment Ops: include COID, money flow / order ID(s), amount & currency.
  12. Reset clears the current form only. Switching boards keeps shared values such as Company ID when the field IDs match.
  13. If a product grid requires extra ENG fields, put them in Product-Specific Details so engineering does not have to ask for a follow-up.
